## 1. 起動時は常に編集専用モード

`src/App.tsx:398–400` は `koharu-editor-mode` の保存値から表示モードを復元する。`src/viewMode.ts:3–5` が `split` / `preview` を受け入れるため、前回プレビューで終了した場合、次回も編集画面だけでは起動しない。`src/App.tsx:479` と `1103` にはモードの保存処理もある。

初期値を常に `edit` にし、起動時の前回モード復元を外す。起動後の分割・プレビュー切り替えは維持する。不要になった保存処理も整理する。

アウトラインは `src/App.tsx:394` で初期表示され、編集モードと独立して描画される。ユーザー回答により、起動時はプレビューとアウトラインの両方を閉じることが確定した。アウトラインの初期値も非表示にし、起動後は表示メニューから開けるようにする。

検証項目:

- 保存値が `edit` / `split` / `preview` / 不正値 / 未設定のどの場合でも編集モードで起動する。
- ファイル関連付けからの起動でも同じ初期モードになる。
- 起動後に表示モードを変更できる。
- 起動時にアウトラインが閉じており、起動後に表示メニューから開ける。

## 2. 書式ツールバーを中心としたアイコン化

`src/components/MarkdownToolbar.tsx:322` と `386` は `action.short` の短縮テキストを表示している。日本語の表示内容は `src/formattingUi.ts` に定義され、太字、斜体、取消、リンク、文中コード等が横幅を使う。

最上段のファイル／表示などのメニュー名と、ドロップダウン項目の文字は維持する。常時見える書式ツールバーの操作をアイコン化することで、探索性を保ちながら幅を削減できる。

| 操作 | 表現案 | 補足 |
|---|---|---|
| 見出し | H ＋下向き矢印 | メニューで H1〜H6 と操作名を示す |
| 太字・斜体・取消線 | 装飾した B / I / S | 一般的な文字装飾の形を用いる |
| リンク | 鎖 | 操作名はツールチップにも表示 |
| 文中コード | `</>` | コードブロックとの形の違いを持たせる |
| 引用 | 引用符 | 書式の引用操作であることを説明する |
| リスト | 箇条書きの線 ＋下向き矢印 | 箇条書き／番号付き／チェックリストを選択 |
| コードブロック | 枠付きコード ＋下向き矢印 | 言語選択があることを示す |
| 表 | 格子 | 同じ線幅の SVG を使う |
| 図 | フローチャート | ツールチップには「図（Mermaid）」を表示 |
| その他 | 三点リーダー | 狭いペインで追加操作を収納 |

操作領域の高さは現行の 32px を下回らないことを提案する。絵文字の混在は避け、線幅とサイズを統一した SVG を使う。既存の `aria-label`、`aria-pressed`、`aria-expanded`、キーボード移動、選択範囲保持を維持し、SVG 自体は支援技術に重複して読み上げさせない。

現在は `title` に説明があるが、アイコン化ではフォーカス時にも読める操作名・ショートカット表示が望ましい。色だけで選択状態を示さず、境界線や背景も利用する。

`src/styles.css:1920` 付近はウィンドウ幅 960px 以下で折り返しと「その他」への収納を行う。分割表示ではウィンドウ全体が広くても編集ペインだけ狭くなるため、編集ペインの実際の幅を基準に収納する案を推奨する。

検証項目:

- 日本語／英語、ライト／ダーク、文字サイズ変更でボタンが欠けない。
- 編集／分割表示と狭いペインでも全操作に到達できる。
- Tab、矢印、Enter、Escape の操作と選択範囲保持が退行しない。
- 各アイコンの操作名、選択状態、メニュー展開状態が支援技術に伝わる。

## 3. メニューの分類を揃える

`src/App.tsx:1451` 付近の「表示」にテーマ・UI 言語・表示モードがあり、`1473` の「設定」には外観だけがある。見た目に関する操作の場所が分散している。「履歴」は独立したトップレベルメニューで、検索はメニューではなく即時実行ボタンになっている。

以下は Koharu に対する推奨構成であり、Windows の必須仕様であると断定するものではない。

| メニュー | 推奨内容 |
|---|---|
| ファイル | 新規、開く、最近使ったファイル、保存、名前を付けて保存、HTML/PDF エクスポート、プロパティ、終了 |
| 編集 | 検索。元に戻す／やり直し等を追加する場合もここへ配置 |
| 書式 | 見出し、文字装飾、リスト、コード、表、図、JSON 整形 |
| 表示 | 編集／分割／プレビュー、アウトライン、書式ツールバー、分割位置リセット、テーマ、外観 |
| 設定 | UI 言語 |
| ヘルプ | 使い方 |

外観を表示へ、言語を設定へ移すだけでも分類は改善する。さらに最近使ったファイルを「ファイル」へ、検索を「編集」へ移すと、最上段メニューと即時操作の役割が揃う。ただし、最近使ったファイルは到達しやすさを損なわない構成とする。

メニュー構造を変更するときは、クリック操作だけでなく、展開後のフォーカス、Escape で閉じた後の復帰、キーボードによる移動を合わせて確認する。

## 4. PDF Export の要求

「ファイル → PDF としてエクスポート…」を HTML エクスポートの隣に配置する。使用頻度が未確認のため、書式ツールバーへの常設は不要と考える。

現行の HTML エクスポートは `src/App.tsx:788` から `markdownToHtml` と `buildStandaloneHtml` を呼ぶ。`src/exportHtml.ts` は独自の変換・スタイル定義であり、画面プレビューと別系統である。そのまま PDF に流用すると、画面で見えた内容との不一致につながる懸念がある。

PDF はプレビューと共通の描画処理を使い、印刷向けスタイルを適用する方針を推奨する。

- 未保存の編集を含む現在の文書を出力する。
- 編集専用モードからも出力でき、画面の表示モードを変更する必要がない。
- 白背景・黒文字、読みやすい余白、印刷向けのリンク色を使う。
- 画像、フォント、Mermaid の描画完了後に出力する。
- 表、長いコード、見出し、図の改ページと折り返しを扱う。
- 保存先選択、生成中表示、二重実行防止、成功・失敗の通知を用意する。
- 保存先選択のキャンセルはエラー扱いしない。
- PDF 出力によって編集中ファイルの保存先や未保存状態を変えない。

受け入れ検証は日本語、複数ページ、表、長いコード、画像、Mermaid、未保存文書を含める。本文の欠落、図の未描画、文字化け、ページ外へのはみ出しを実際に生成した PDF で確認する。キャンセル、出力失敗、連続実行時の挙動も確認する。

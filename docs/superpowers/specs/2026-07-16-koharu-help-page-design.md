# Koharu 使い方ヘルプ 設計

## 目的

Koharuを初めて使う人が、外部サイトを参照せずに基本操作を理解できる、簡潔なアプリ内ヘルプを提供する。編集中の文書や未保存状態には影響を与えない。

## 対象範囲

ヘルプでは次の内容を日本語と英語で案内する。

- ファイルの新規作成、開く、保存、名前を付けて保存
- エディターでの文章入力
- 見出し、太字、斜体、箇条書き、リンクのMarkdown書式例
- Markdownプレビューの表示と非表示
- 文書内検索
- 新規、開く、保存、検索、太字、斜体、プレビュー切替の主なショートカット

Wikiリンク、コマンドパレット、Vaultなど、Koharuから削除された機能は説明しない。Mermaid、Excalidraw、相対Markdownリンクなどの高度な機能も、初心者向けの初回ヘルプには含めない。

## UIと操作

- メニューバーに「ヘルプ」メニューを追加する。英語UIでは `Help` と表示する。
- メニュー内の「Koharuの使い方」を選ぶと、編集画面の上にモーダルを表示する。英語UIでは `How to use Koharu` と表示する。
- モーダルは見出しごとの短い説明、Markdown書式例、ショートカット一覧で構成する。
- 右上の閉じるボタン、下部の「閉じる」ボタン、`Esc`キーで閉じられるようにする。
- 小さいウィンドウではモーダル本文だけを縦スクロールできるようにする。
- ヘルプ表示中は背面の編集操作を受け付けず、閉じた後は編集を続けられる。

## コンポーネント構成

ヘルプ本文と閉じる操作を担当する `HelpDialog` コンポーネントを追加する。表示状態は既存の `App` が管理し、メニュー操作で開き、`HelpDialog` のコールバックで閉じる。

表示文言は既存の日英テキスト定義と同じ言語状態に従う。ヘルプ固有のまとまった文言は `HelpDialog` 側で言語別に保持し、アプリの言語を切り替えると再表示なしで内容も切り替わる。

## 状態とデータの流れ

1. 利用者が「ヘルプ」から「Koharuの使い方」を選ぶ。
2. `App` がヘルプの表示状態を有効にし、開いていたメニューを閉じる。
3. `HelpDialog` が現在のUI言語に合う内容を表示する。
4. 閉じる操作または `Esc`キーで表示状態を無効にする。

ファイル内容、現在のファイルパス、保存状態、プレビュー状態は変更しない。

## アクセシビリティ

- ダイアログには `role="dialog"`、説明可能な見出し、モーダルであることを示す属性を付ける。
- アイコンだけの閉じるボタンにも日本語または英語のラベルを付ける。
- `Esc`キーで閉じられるようにする。
- Markdown例とショートカットは、装飾だけに頼らず文字として読めるようにする。

## エラー処理

ヘルプはアプリ内の固定情報のみで構成し、ファイル読込やネットワーク通信を行わない。このため、通常の利用で個別のエラー表示は必要ない。

## テスト

- ヘルプメニュー用の日英ラベルが定義されていること。
- 日本語と英語で、基本操作、Markdown書式例、ショートカットが表示されること。
- 閉じるボタンが指定された処理を呼ぶこと。
- ダイアログとして必要な属性が付いていること。
- `Esc`キーで閉じる処理が呼ばれること。
- 既存の全フロントエンドテスト、TypeScript/Viteビルド、Tauri側の確認が成功すること。

## 完了条件

- 初心者がメニューバーからヘルプを見つけ、基本操作を日英どちらでも確認できる。
- ヘルプを閉じた後、編集中の文書と未保存状態がそのまま保たれる。
- 削除済み機能や高度な機能を案内せず、内容が簡潔に保たれている。

# Koharu ヘッダー簡略化とBuild表示移動 設計

## 目的

メニューバーと編集領域の間にある情報帯を削除し、その分だけ編集領域を広くする。必要なBuild番号は既存の下部ステータスバーへ移動する。

## UI変更

- メニュー下にある `Koharu`、Build番号、更新日時、「単一ファイルテキストエディタ」を表示する帯を完全に削除する。
- ヘッダーはメニューバー1段だけにする。
- Build番号は下部ステータスバーの一番右に `build 20260716.234245` の形式で表示する。
- 更新日時と「単一ファイルテキストエディタ」は、別の場所へ移さず画面表示から削除する。
- Windows標準のタイトルバーは変更しない。

## 維持する表示

下部ステータスバーの次の情報と動作は維持する。

- 現在のファイルパス
- 保存済み・未保存の状態
- プレビューのオン・オフ
- 行数
- 文字数

Build番号はこれらの後ろに追加する。狭い画面でも折り返さず、他のステータスと同じ控えめな文字で表示する。

## 実装方針

- `App` から上部の `window-caption` 要素を削除する。
- 既存の `BUILD_INFO.buildNumber` を下部ステータスバーで参照する。
- ヘッダーのCSSを2段構成から1段構成へ変更する。
- `window-caption`、`build-badge`、`build-updated` 専用CSSを削除する。
- Build表示の文字列生成を小さな純粋関数にし、画面構造とは独立してテストする。

## レスポンシブ表示

小さい画面向けに残っている `window-caption` のレイアウト指定も削除する。Build番号には `white-space: nowrap` を指定し、下部ステータスバーの右端で1行表示を維持する。

## テスト

- Build番号が `build <buildNumber>` の形式になることを自動テストする。
- `App` 内に上部の `window-caption` が残っていないことを確認する。
- 下部ステータスバーでBuild番号が表示されることを確認する。
- フロントエンドテスト、TypeScript/Viteビルド、Rustチェックを実行する。

## 完了条件

- メニューバー直下から余分な情報帯がなくなり、編集領域が上へ広がる。
- Build番号を下部ステータスバー右端で確認できる。
- 既存の編集、プレビュー、保存状態、行数、文字数の表示と操作が変わらない。
